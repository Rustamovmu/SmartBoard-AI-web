# SmartBord website

Use this established separate Next.js 16.4.4 Pages Router checkout. Do not convert to App Router or move it into the backend/mobile repository. Read README, docs/Verification.md and the backend's current authentication contract/plans before edits. Use Node 24, Yarn 1.22.22 and yarn.lock; `yarn run check` runs TypeScript, while `yarn check` is Yarn's built-in command.

Preserve real backend current-account/status authorization, Secure/HttpOnly/Strict cookies, exact HTTPS origins, per-POST CSRF and cross-tab credential serialization. Never put tokens in URLs, localStorage, sessionStorage, page props or logs. Keep SSR data/cache request-scoped and account responses no-store. Strict single-use refresh cannot be retried after an ambiguous/lost response. The only browser storage is a credential-free uncertainty marker. Unsupported session coordination must fail safely.

Private lectures/media/notes/OCR/catalog remain on devices. No web account page may fetch a phone library, upload/sync private content or erase files on logout/blocking. Do not fabricate saved captures, AI output, admin services or links to unimplemented functionality.

Inspect the worktree before edits and explicit staging; preserve user changes. Use focused local commits for completed changes, report hashes, and do not push/amend/rebase. References in ../tripLInk-next and ../nestar-next are read-only; their policies do not create additional approval gates here. Keep temporary hosts loopback-only and stop your own services after checks.

Run `yarn run check`, `yarn lint`, `yarn build` and appropriate real browser verification. Use the dedicated test URI only and exact guarded disposable DBs; never application fixtures or a real admin. Normal `yarn dev` serves local HTTPS plus an API TLS bridge to a separately started backend on 4001; `yarn dev:http` is layout-only and disables auth fields. `yarn setup:https --trust-local-ca` explicitly provisions ignored persistent localhost certificates and user SSL trust. The browser harness can reuse that trust with `--dev --local-cert`, or installs temporary constrained CA trust after an explicit `--trust-local-ca` opt-in, verifies TLS without bypass flags, and removes only its own certificate/trust/files and DB. Record actual results and failures; browser checks do not establish native-phone or deployment-wide acceptance.

Admin account UI now lives at `/admin/users` (with `/admin` redirect). Keep deleted accounts read-only and backend last-admin decisions authoritative. Apollo requests share the auth/CSRF lock; never nest the lock, cache directory data, or automatically retry an uncertain mutation. `yarn graphql:sync` explicitly copies the backend schema artifact; `yarn graphql:generate` uses the committed local snapshot; `yarn graphql:check` checks schema/generated drift. Run the existing browser harness with `--admin` in development and production modes for account management, using guarded synthetic administrators only. Comments and reports now add public discussion, protected `/account/comments` and `/account/reports`, and `/admin/comments` and `/admin/reports`. B3/F1 physical-phone proof remains incomplete.

Public Help requests must use the fixed API origin, `X-SmartBord-Client: public` and `credentials: omit`, without Cookie/Authorization/CSRF or session refresh. Never weaken the private browser/native transport. Preview/public Markdown share the restricted renderer, with no raw HTML, images, embedded media or MDX. New entries are drafts; publishing/live edits/unpublishing/archiving require confirmation and expected revisions. Restore only to draft. Keep editor buffers in memory, preserve them during successful same-actor checks and clear them on revocation/logout. The layout's cancelable navigation event must run before clearing editor state. Run `test:web` with `--help` in both transports; it includes auth/admin regressions and uses only guarded disposable databases. Application index setup and real content publication are separate operator actions, not startup seeds.

Community drafts are explicitly saved server text visible to administrators; disclose this before saving. Administrators inspect/remove with a reason or restore only to draft; removed posts are read-only for authors. Removal/withdrawal retain text, with no permanent deletion in V1. Account blocking does not automatically hide published posts. Reuse restricted Markdown, revision checks, protected editor lifecycle and uncertainty reconciliation. `test:web --community` includes auth/admin/Help regressions and must pass in both transports. Keep Help/community index rollout separate: prepare and verify required indexes before updating running services; this feature's source/tests do not execute application setup or deployment.

Comments publish immediately after explicit confirmation; there is no new-comment server draft. Owners edit/withdraw/republish with expected revisions; removed comments are locked. A hidden parent suppresses public comments and prevents editing/publication/reporting; owners can still withdraw via a state-only change. Administrator restoration always produces a withdrawn draft. Report history is private to the reporter/admin, without reporter IDs in DTOs. OPEN reports can become RESOLVED/DISMISSED; review alone never removes content. Inspect exact current target text and moderate separately. All content/report writes share the existing 20/account/minute budget, with a separate 10/account/minute report-submission budget.

Keep discussion reads credential-free and protected forms behind the existing account/admin lifecycle. All unsent text stays in memory, with navigation guards and clearing on revoked identity/logout. Uncertain/stale writes lock mutation controls until successful read-only reconciliation. Use `yarn test:web --dev --local-cert --discussion` and production `yarn test:web --local-cert --discussion` for the full auth/admin/Help/post/discussion regression. `--discussion-focus` is iteration-only and omits older content/admin groups; it is not full regression evidence. Password recovery now uses `/reset-password`, linked from login. Accept an operator-issued code only through the masked manual form; no URL prefill, proof issuer, automated email request or auto-login. Use the existing cross-tab auth lock for CSRF and the entire reset response, without `/me` or refresh. Passwords are confirmed locally and not trimmed. Clear fields after attempts/history/session notifications; keep proofs/passwords out of React state, page props, storage, logs and artifacts. The only persistent state remains the existing credential-free uncertainty marker; preserve any pre-existing marker on deterministic 4xx errors, and prevent refresh after an ambiguous reset. Unknown/5xx/lost responses must not replay the single-use code. Require normal login after success. Tests use `--recovery` in both HTTPS transports, with fixed guarded synthetic recovery identities and private IPC only; no production issuer or application-account reset is authorized by tests.

Preserve username/email shared login budgets and the required unique sparse index. Confirm the choice and reconcile uncertain/conflicting responses with a read before another write; no mutation replay. Run test:web with --username separately from --recovery in both HTTPS transports; username mode includes the fixed admin regression population. See [username contract](../SmartBord-AI/contracts/usernames.md).
